# 视觉记忆植入增强第三版

用户于二〇二六年十一月十七日授权，以合理且明确登记的方案补充困难负例、零点三对比间隔和对抗查询增强。[原论文第3.2节](https://arxiv.org/html/2604.16966v1#S3.SS2)提及三项机制，但没有公开足以唯一确定实现的公式与参数。本版本补齐可运行机制，不宣称与作者未公开的内部实现逐项相同。

## 作用与实现约定

- 困难负例给当前图片安排更有竞争力的候选。九十个冻结公开商品仍共用；每条查询按相似度选出最多三十二个负例，覆盖同类商品、独立公开代理记忆和热门分支，去重后不足部分从全库最相似条目补齐。选择随实际查询向量变化，不按正式评估名次挑选。
- 对比间隔要求图片在竞争中建立更大优势。正例的归一化余弦相似度先减零点三，再与负例一起除以检索温度零点零七并计算归一化损失。它融入检索项，三项联合总损失及原有权重不变；这是一项明确的公式补足约定。
- 对抗查询增强让图片面对更难匹配的查询向量。对冻结文字编码做三步梯度上升，增加当前检索损失；查询维持单位范数，与原向量的欧氏距离最多零点零五，每步长度零点零二五。保留每条查询遇到的最坏结果，再将干净查询损失和增强查询损失各半混合。内层图片与候选均无梯度，外层只更新图片，不修改实际查询文字。

查询向量的零点零五预算与图片的八除以二百五十五预算属于不同空间，不能互换。向量增强没有调用语言模型生成新句子，也没有增加或改写冻结的一百条训练文字。

## 公开代理来源与限制

正式共享记忆和正式测试查询仍禁止参与训练。同类分支按冻结候选的公开品类确定；代理记忆分支使用独立公开候选，明确登记为真实用户记忆的替代。热门分支优先使用有公开来源凭证的热度数值；当前九十商品清单没有销量或热度字段，因此使用固定候选向量之间的语义中心性，先取最典型的前三分之一作为热门代理池。

语义中心性不是销量。运行证据必须说明使用的是中心性代理，不能称为真实热门销售榜，也不能称已读取用户既有记忆。三种选择视角可以来自同一个独立公开库，实际候选去重；默认各申请八个名额，总数以可用候选和三十二个上限为准，来源不足及重合补位均记录在证据中。

## 版本与兼容性

`mechanism_profile`(机制版本字段)取 `enhanced_v3`(增强第三版)时启用三项机制；取 `legacy_v2`(历史第二版)时保留原三项损失、全固定负例与无查询增强的行为。无配置、空配置和命令行部分覆盖默认使用增强第三版；历史配置明确包含目标模式但缺少机制版本时，按历史版本解释。新版配置示例是 `src/visual/config/visual_inception.example.json`。

增强目标身份为 `visual_inception_retrieval_semantic_perceptual_hardneg_advquery_v3`(含困难负例、对比间隔和对抗查询增强的三项联合目标)。旧无检索和第二版记录继续按原身份校验，旧图片不能改标签成为增强版；同一次九组评估也不能混用第二版与第三版。

默认三类代理、图像百步优化、图像预算、语义权重一、感知权重零点一、五十／三十／二十训练文字及小批量十六均沿用。正式训练仍只消费冻结公开训练包，数据不完整时在装载大型权重前停止。

## 评估身份与跨组缓存

评估隔离以成图中实际冻结的训练代理身份为依据，合并同一修改库内全部替换图片的代理，并将模型、预训练身份、权重摘要及图片绑定写入评估计划。独立复算继续使用该上下文，避免自定义代理或大写巨型代理被误报为留出模型。没有成图上下文的直接调用按全部内置方案动态枚举，采取保守检查。同代理模式还须匹配实际权重摘要；真正的小写巨型留出结构保持独立。

固定候选缓存采用独立新版身份，按图片字节及顺序、实际代理、预处理、设备与数值运行时复用；每次请求的训练包摘要保留在外层证据中。相同公开候选不因组别概念或查询不同而重新编码。各组须使用共同缓存目录，增强配置示例已指定该目录；未传配置时继续使用各成图目录内的独立缓存。旧版缓存只按原包绑定核验，不迁移或改签新版。

## 本地验证范围

本地使用微型合成图片和显式模型夹具验证负例选择、间隔梯度、查询球面预算、最坏损失、内外层梯度隔离、新旧证据及入口版本。真实大型代理的显存、速度、扰动自然度和迁移效果须另行远程验证，不能用本地微型测试结果代替。

增强审计覆盖全部校准起点、每个优化步骤和最终全查询检查，保存逐查询负例及增强预算证据。按默认日程和九十候选使用随机向量序列化估算，单份生成元数据约六十二兆字节，两份证据及九组结果会增加磁盘和同步开销；该数值是结构估算，不是真实模型运行结果，实际体积随配置变化。
