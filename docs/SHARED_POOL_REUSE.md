## 固定对照直接复用

九组原始像素图已经完整导入根输出目录的历史基线目录。第一至六、第八和第九组来自十一月九日，第七组来自十一月十二日后期重选实验。参数均为八除以二百五十五、完整一千步、种子四十二和文字权重一；实际落盘图片逐组核验通过。原始证据保留原字节，活动读取函数动态定位当前项目路径，不依赖来源项目存在。

基础包入口的原始像素生成阶段现在只登记这九张既有图，不训练、不调用编码器；参数不符则停止。低层通用生成接口仍供其他明确的新实验使用。后续九组主比较只需生成新环境光协同方法的图片。

```bash
python -B -X utf8 tools/run_experiment.py generate --group all --method lucid --output output/comparison_groups9 --device cpu
python -B -X utf8 tools/run_experiment.py generate --group all --method ambilage --output output/comparison_groups9 --device cuda
```

历史原始像素训练使用原记录中的快速激活设置，这一事实保留，不冒充当前加载器的新执行结果。旧检索排名也只作历史证据；新库、新编码器和九图同时替换条件下需要重新评估对照，复用成图不等于直接沿用旧排名。

## 同一完整库内同时替换九张图

正式评估开始前，方法对应的全部九张图必须完成并冻结。每个方法统一构建一个一百八十九条的原图库和一个修改库，修改库同时替换九条源参考的检索图片。九组请求都面对这同一个完整库，不能逐组建立各自只改一张图的库。

无防御时，一百八十条正常记录完全原样，九条源参考仅增加检索图片替换字段。商品名、品牌、特点、历史、来源和购买标记不变，基础库始终只读。有防御时，对两个完整库的所有图片采用同一条件。各组共用同一条件下的库文件及摘要。

```bash
python -B -X utf8 tools/run_experiment.py evaluate --group all --method lucid --output output/comparison_groups9 --device cuda --query-mode text --defense-mode none --evaluation-name g14
python -B -X utf8 tools/run_experiment.py evaluate --group all --method ambilage --output output/comparison_groups9 --device cuda --query-mode text --defense-mode none --evaluation-name g14
```

当前正式文字及目标特点不改变；图文模式仍需明确准备本组独立查询图片，不回退到商品原图。完整防御面板可在独立评估名称下显式运行，不复用不同范围的冻结计划。

## 只更新实际变化的记忆向量

记忆向量按图片摘要、完整公开文字摘要、模型权重与分词器身份、预处理、解码器、融合权重和数值运行时寻址，不再因为整个库的摘要变化而全部失效。

同一编码条件下，原图库首次建立一百八十九条向量；九图修改库复用一百八十条未变记录，只为实际改变的九条编码。后续组请求及另一方法继续复用内容未变且身份相同的条目。不同防御条件分别按实际图片身份缓存。缓存位置为本轮输出目录的 memory_vectors（记忆向量目录），属于必要实验输入证据，可随私有仓库保存。

更换评估编码器、文字、融合规则、预处理或数值运行时后，需要新建相应向量，不能把旧小型编码器向量改名当成巨型模型结果。缓存损坏会拒绝复用并重建，不改变图像或请求。独立复算仍另起进程、关闭继承缓存、重新编码全库，核对全部候选分数，不能以缓存自证正确。

本轮只进行输入复制、历史成图核验、路径与摘要检查及微型逻辑测试，没有重新训练对照、生成新方法图片或进行真实模型检索。
